# RVCE Campus Navigator — Comprehensive Bug Audit & Resolution Report

> Every defect listed below was discovered through static analysis, build execution, live API inspection, or runtime emulator debugging, and resolved at the root cause.

## Summary by Severity
- **Critical (Build / Startup / Data Connectivity / Physical Touch Blockers)**: 5 Found → **5 Fixed & Verified**
- **High (Core Navigation / Auth / Map UX Defects)**: 6 Found → **6 Fixed & Verified**
- **Medium (Visual Polish / Schema Governance / Edge Handling)**: 4 Found → **4 Fixed & Verified**

| **BUG-01** | **Critical** | Native C++ / Gradle Build (`mobile/android`) | `assembleDebug` and `assembleRelease` failed in Ninja (`Filename longer than 260 characters`) on `react-native-worklets`, `react-native-reanimated`, and `:app` codegen. | Out-of-tree C++ JSI sources (`../Common/cpp/...`) combined with a workspace path containing spaces (`C:\Users\mohit\RVCE\5th sem\DBMS\DBMS LAB EL\...`) produced 302-character `.cxx` object file paths exceeding Win32 `MAX_PATH` (260). Furthermore, `com.facebook.react` configures `:app` CMake late in evaluation. | Configured short CMake staging roots (`C:/cx/a` for `:app` and `C:/rvce_cxx/${subproject.name}` for library modules) with `-DCMAKE_OBJECT_PATH_MAX=220` across `mobile/android/build.gradle` and `mobile/android/app/build.gradle` so CMake MD5-hashes long codegen filenames (`ComponentDescriptors.cpp.o`) without exceeding 225 chars. | `.\gradlew.bat assembleRelease` compiles both `arm64-v8a` and `x86_64` C++ targets cleanly (exit code 0). |
| **BUG-02** | **Critical** | Mobile Networking (`api.ts`, `AndroidManifest.xml`) | Mobile app showed `"Failed to fetch"` / `"Offline Cache"` even while FastAPI, MySQL, and MongoDB were running healthy on the host machine. | Two compound causes: (1) `uvicorn` runs bound to `127.0.0.1:8000` whereas `api.ts` hardcoded `http://192.168.1.7:8000/api/v1`; (2) Android 9+ blocks cleartext `http://` requests in Release builds unless explicitly permitted. | Added Smart Endpoint Auto-Discovery in `api.ts` probing `http://10.0.2.2:8000/api/v1` (Emulator), `http://127.0.0.1:8000/api/v1` (USB `adb reverse`), and `http://192.168.1.7:8000/api/v1` (LAN), plus `android:usesCleartextTraffic="true"` in `AndroidManifest.xml`. | Emulator connects automatically to live FastAPI (`Server Online` green pill, MySQL & MongoDB connected). |
| **BUG-03** | **Critical** | Standalone APK Packaging (`app/build.gradle`) | Debug APK (`assembleDebug`) requires a running Metro bundler (`debuggableVariants = ["debug"]`) and fails with `"Unable to load script"` when installed standalone on a phone. | React Native skips JS bundle embedding for `debug` variants by default. | Built standalone `assembleRelease` APK bundling ahead-of-time Hermes bytecode (`index.android.bundle`) for both `arm64-v8a` and `x86_64`, with `enableMinifyInReleaseBuilds=false` to preserve MapLibre/Reanimated JNI reflection symbols. | Standalone APK launches cold on `emulator-5554` with zero Metro server running. |
| **BUG-04** | **High** | Outdoor Routing (`campusRouter.ts`, `NativeCampusMap.tsx`) | Earlier mobile app drew a straight 2-point line cutting across campus buildings when offline, whereas the web app followed campus roads and footpaths. | Initial mobile catch-block returned a 2-coordinate fallback line instead of executing graph routing; walkway/road visual casing also differed from the web baseline. | Ported exact Python Dijkstra router (`479` edges / `415` nodes) to `mobile/src/services/campusRouter.ts` and styled `DRIVE` legs with double-line blue/white casing and `WALK` legs with crimson red dashed pathways (`#DC2626`) matching the verified campus map. | `64/64` Vitest parity tests pass (<0.5m node tolerance vs Python backend) + visually verified on emulator. |
| **BUG-05** | **High** | Staff Auth & Availability (`profile.tsx`, `StatusPill.tsx`) | Demo sign-in buttons failed (`401 Unauthorized`), and availability updates failed schema validation (`422 Unprocessable Entity`). | `profile.tsx` hardcoded non-existent credentials (`hod.cs` / `Admin@123`) and non-existent enum literals (`IN_CLASS`, `IN_MEETING`, `ON_LEAVE`) instead of backend Pydantic `Literal['AVAILABLE', 'BUSY_SCHEDULED', 'UNAVAILABLE', 'UNKNOWN']`. | Aligned `StatusPill.tsx` and `profile.tsx` to exact FastAPI/MySQL enums and real seeded accounts (`hod.cse`, `faculty.cse`, `security.desk`, `sysadmin` / `RvcePortal@2026`). | Verified live login, availability broadcast, and Gate Check-In against FastAPI + MySQL. |
| **BUG-06** | **High** | Map Controls & Camera Sync (`NativeCampusMap.tsx`) | Map floating controls (`top: 16`) and attribution pill (`top: 16`) collided directly with the floating top search bar; selecting a building from Home or Directory did not move the MapLibre camera. | Absolute positioning ignored the floating search header height, and `NativeCampusMap` lacked `useEffect` hooks observing `selectedBuildingId`, `selectedFacilityId`, and `activeRoute` bounds. | Repositioned right FABs to `top: 152` and attribution pill to `bottom: 12` (auto-hiding behind active bottom sheet); added `flyTo` / `fitBounds` camera synchronization hooks. | Visually verified via emulator screenshots (`02_explore_map.png`, `03_building_sheet.png`, `04_dijkstra_route.png`). |
| **BUG-07** | **High** | Indoor Navigation (`IndoorFloorModal.tsx`, `map.tsx`) | Core journey `Building → Floor → Indoor Floor Plan → Room` was missing on mobile (only `Directions` existed on building selection). | Indoor SVG viewer had only been implemented on the React web client. | Engineered native `IndoorFloorModal.tsx` using `react-native-svg` with floor chips, zoom controls, interactive room selection, faculty occupant lookup, searchable room index, and `SAMPLE_DEV` governance notice. | Verified in `IndoorFloorModal` on Android emulator (`05_indoor_floor_plan.png`). |
| **BUG-08** | **High** | Map Routing UX (`map.tsx`) | Users could not choose a custom start building (`Set Start`), swap origin/destination, or toggle `Walk` vs `Drive` while viewing an active route without clearing and restarting. | Route origin was hardcoded to `GPS ?? | **BUG-09** | **Medium** | Facility Map Markers (`NativeCampusMap.tsx`) | All 12 campus facility markers rendered as grey fallback dots instead of category colors. | Marker switch checked `FOOD_COURT`, `MEDICAL`, `ATM` instead of actual MySQL categories `CAFETERIA_FOOD`, `MEDICAL_FIRST_AID`, `BANK_ATM`, `GATE_RECEPTION`, `LIBRARY`. | Aligned marker colors and icons to all 8 exact MySQL facility categories. | Verified distinct colored facility markers on Explore Map. |
| **BUG-10** | **Medium** | Design System Compliance (`profile.tsx`, `index.tsx`) | `profile.tsx` used purple demo banner styling (`#FAF5FF` / `#6B21A8`), violating `apk_ui_prompt.txt` Section 3.2 ("Do not use excessive purple"); Home header title read `RVCE Campus Guide` instead of `RVCE Campus Navigator`. | Legacy styling from initial draft. | Replaced purple accents with RVCE Navy / Light Blue (`#27447E` / `#EDF2FA`) and standardized product title to `RVCE Campus Navigator`. | Visually verified across all 5 tabs. |
| **BUG-11** | **Medium** | Error State Handling (`api.ts`) | Valid HTTP 401/422 responses (such as wrong login password) previously caught in generic `catch` block and marked the backend connection as `OFFLINE_FALLBACK`. | Network errors and HTTP 4xx/5xx status errors were conflated. | Introduced `ApiHttpError` class so HTTP responses keep `connectionState = 'ONLINE'` while surfacing the server's `detail` message cleanly. | Tested invalid login in Journey E; server badge stays green `Server Online`. |
| **BUG-12** | **Medium** | Server Settings Presets (`server-settings.tsx`) | Previously showed a non-existent placeholder Cloudflare URL (`rvce-campus.trycloudflare.com`). | Hardcoded example domain. | Replaced with honest real presets (`10.0.2.2:8000` Emulator, `127.0.0.1:8000` USB `adb reverse`, `192.168.1.7:8000` Wi-Fi LAN) plus custom URL input for live `start-tunnel.bat` URLs. | Verified in Server Settings modal. |
| **BUG-13** | **Critical** | App Entry Point (`mobile/index.ts`) | Initial emulator launch rendered boilerplate `"Open up App.tsx to start working on your app!"` instead of the Expo Router 5-tab application. | `create-expo-app` scaffold left `index.ts` importing `./App` rather than `expo-router/entry`. | Caught via live emulator `uiautomator dump`; updated `mobile/index.ts` to `import 'expo-router/entry';` and rebuilt `index.android.bundle` (`1,948` modules). | Verified live on `emulator-5554` (`01_home.png`, `02_explore_map.png`). |
| **BUG-14** | **Critical** | Physical Android Map Touch & Compositing (`NativeCampusMap.tsx`) | On physical Android devices, building polygons did not respond to taps, `GLSurfaceView` interfered with overlay touch targets, and route endpoint pins blocked underlying markers. | (1) MapLibre v11 Fabric passes `NativeSyntheticEvent<PressEventWithFeatures>`, so features live at `e.nativeEvent.features` and coordinates at `e.nativeEvent.lngLat` (`e.features` was `undefined`); (2) default `androidView="surface"` (`GLSurfaceView`) causes Android Z-order punch-through over React Native overlays; (3) marker pins lacked inner `TouchableOpacity` hitboxes and `pointerEvents="none"` on endpoint pins. | Switched `<Map>` to `androidView="texture"`, unwrapped `e.nativeEvent.features` / `e.nativeEvent.lngLat`, added dual-dispatched `TouchableOpacity` + `<Marker onPress>` with `280ms` deduplication, converted route `A`/`B` markers to GPU `CircleLayer`s + `pointerEvents="none"`, and replaced manual zoom estimation with `cameraRef.current.fitBounds(...)`. | TypeScript + Vitest (`73/73`) verified; packaged into `v2.1.0` (`versionCode: 3`). |
| **BUG-15** | **High** | From (A) / To (B) Navigation Planner (`map.tsx`, `index.tsx`) | Users on mobile had no top-level `Directions` button to open an `A → B` route planner directly, and `From (A)` / `To (B)` rows on active routes were plain non-interactive `<Text>` labels without searchable building/facility selection or `"Tap on Map"` picking. | Initial `map.tsx` required tapping a marker first and lacked a dedicated Google-Maps-style `From` / `To` planner modal matching `CampusMapPage.tsx` on web. | Built a full `From (A)` & `To (B)` Campus Navigation Planner with top-bar `Directions` button + `Route A → B` chip, tappable `From (A)` and `To (B)` rows opening a full-screen searchable modal across all 28 RVCE buildings + 12 amenities + Main Gate + Live GPS, interactive `"Tap on Map"` pin-drop mode, `Walking` / `Vehicle` switcher, `Swap (⇅)`, and collapsible Turn-by-Turn steps. | Verified static types (`tsc --noEmit` exit 0) and unit suites (`73/73` pass). |
